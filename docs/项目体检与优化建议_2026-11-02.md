## 二、关键发现

### 2.1 做得好的部分

- **CI 是真的门禁**：不只跑单测，还跑基准与回归校验。
- **负结果留档**：7.2 双语自举、7.4 语义重排都有量化与"不采纳 / 默认关闭"的结论。
- **边界清楚**：HIL 不替代 Harness 的 Agent Loop / 上下文压缩，只做项目上下文与工程记忆。

### 2.2 主要缺口：`raw` 召回 70.8%，离 90% 还有距离

- 已确认主因不是"没召回文件"，而是**窗口排序在纯中文查询下退化**（`missing_symbols`）。
- 7.1 人工术语表、7.2 自举表都试过：后者会拉低 `hinted`，已回退。
- 7.4 语义模型能 +1.0pp，但延迟远超"检索 p95 < 1s"的退出标准。
- 下一步应**先定义可接受的延迟预算**，再决定是否做缓存 / 批量化 / 小模型量化；否则不要默认开启。

### 2.3 文档内部有一处未裁决的冲突

- `docs/overview.md` §7 声明"HIL 不监听文件变化"；
- `docs/roadmap.md` 又把"文件监听"列入待做。
- 这是产品边界问题，不是实现问题；需要一次明确裁决并回写两处。

### 2.4 CI 只跑 Ubuntu

- 用户实际在 Windows 上使用；路径、编码、`rg` 行为可能不同。
- 建议加一个 `windows-latest` job，至少跑单测；基准可只在 Ubuntu 跑。
